# Architecture decisions

- Keep the BIG IDIA Radio console mounted inside the authenticated layout and hide it with a native dialog; provider playback must survive console closure and in-app navigation, but stop on sign-out.
- Use official provider playlist embeds for the two radio decks; keep provider credentials server-side for catalog sync because embedded playback manages its own authorization and must not expose secrets.
- Per-user Spotify/Apple Music linking goes through the music-accounts edge function; provider tokens live only in service-role tables because users' credentials must never reach other clients (MusicKit's developer token is served at runtime since MusicKit JS requires it in the browser).
- Keep Trading Desk API Access as a Data Marketplace panel rather than a standalone navigation page so data access tools share one workspace.
- The Vulture's vulture_ledger and vulture_quarantine are append-only (DB trigger + browser writes revoked); payloads are encrypted at insert by a DB trigger with a Vault-held key and decrypted only via vulture_read_payload (owner/C-suite, aal2, audited), so keys never cross the wire. Only anchoring fields may change, set by vulture-notarization-relayer, which anchors just the Merkle root of sanitized_hash values on Base so CJIS metadata stays off-chain.
- CJIS-isolated Vulture data (node flag, payload flag, or `<owner>/cjis/` upload path) is written only to vulture_ledger and never to mesh_telemetry_events or bundles; PII keys, the 90-day node-key window and Merkle rules live in supabase/functions/_shared/vulture-cjis.ts so both intake paths stay identical.
- Vulture access requires an aal2 (authenticator-app) session, enforced in RLS via is_aal2() and in mesh-nodes, with MfaGate (30-minute idle lock) as the UI step; mesh_nodes is written only by the mesh-nodes function (no deletes, revoke/rotate audited to security_events) to preserve node attribution. Mesh node keys live only as SHA-256 hashes.
- Privileged edge functions (crazy-8-security, security-event-generator, synapse-controller) authorize callers through _shared/edge-guard.ts (service key, internal secret, or super_admin/security_operator in user_roles; synapse-controller also lets users bill only themselves) and restrict CORS to IDIA domains, because these functions run with full database rights.
- Crazy 8 security agents run from a scheduled sweep that reads real activity tables; OpenAI (Lovable AI Gateway) is called only when a signal is notable, and message text or account ids are never sent to the model, so quiet periods cost nothing and no personal data leaves the database.
- Security event details reach the browser only through get_security_event_detail (counts-only signals for ordinary users, full record for super_admin/security_operator) and resolution only through resolve_security_event, because security_events stays service-role-only while security_ticker is the public sanitized feed.
- Crazy 8 agents each enforce one fixed role (Sentinel anomaly detection, Oracle predictive modeling, Hunter threat hunting over logs/ledger, Guardian zero-trust access, Gatekeeper ingress/egress sanitization, Shield quarantine/DLP, Mirror real red-team probes, Insight forensic incident records) with per-role report shapes and cause-based headlines, so reports never duplicate each other.
